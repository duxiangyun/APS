## 一、产品概述

### 1.1 产品定位

本产品是一款面向**多品种、小批量、定制化程度高**的离散制造企业的**智能高级计划与排程系统（APS）**。它以运筹优化算法为核心引擎，在**有限产能、物料齐套、工艺顺序、换型时间**等多重现实约束下，自动生成**精准到工序、设备、班次级**的可执行生产计划，并支持**实时监控、异常预警与动态重排**，帮助企业实现**计划与执行一体化闭环管理**。

### 1.2 核心理念

> **数据驱动决策，算法创造价值，闭环持续优化。**

产品不只是一个"计算工具"，而是一个**能实时应对变化、持续自我进化**的智能生产决策中枢。

### 1.3 目标客户画像

| 维度 | 特征描述 |
|:---|:---|
| **目标行业** | 汽车零部件、电子制造、装备制造、医疗器械、精密加工、印刷包装 |
| **企业规模** | 年产值1亿元以上，设备/产线数量50台（条）以上，计划员≥3人 |
| **核心痛点** | 订单变更频繁、工序复杂、换型时间长、设备昂贵、准时交付压力大 |
| **现有系统** | 已部署ERP（如SAP、用友、鼎捷），部分已上MES |

### 1.4 目标用户角色

| 角色 | 核心诉求 | 使用功能 |
|:---|:---|:---|
| **生产计划员** | 快速产出可执行的生产/采购计划 | 一键求解、结果查看、甘特图、手动调整 |
| **计划主管** | 多方案对比、审批发布计划 | What-if 分析、方案对比、计划审批 |
| **生产经理** | 掌握产能利用与交付风险全貌 | KPI 看板、产能分析、延期分析、异常告警 |
| **采购员** | 获取采购计划与物料短缺预警 | 采购计划、物料告警 |
| **IT 管理员** | 系统配置与集成维护 | 约束/目标配置、ERP/MES 集成、用户权限 |

### 1.5 产品价值

| 价值维度 | 传统模式 | 本产品 |
|:---|:---|:---|
| 排产效率 | 人工排产，数小时甚至数天 | 算法求解，分钟级生成方案 |
| 交付准确性 | 经验估计，经常逾期 | 基于产能约束的精确交期承诺 |
| 产能利用率 | 依赖老师傅经验，设备忙闲不均 | 全局优化，瓶颈优先保障 |
| 应变能力 | 插单/故障后需重新手工排产 | 增量重排，锁定已开工部分 |
| 持续改进 | 计划与执行脱节，无法反馈优化 | 闭环反馈，持续修正模型参数 |

### 1.6 产品核心能力总览

| 能力维度 | 能力说明 | 对应章节 |
|:---|:---|:---|

| **场景管理能力** | What-if 模拟、多方案对比，支持计划员科学决策 | 5.2 / 5.3 |
| **闭环优化能力** | 计划→执行→反馈→优化的持续改进闭环 | 3.2 |

### 1.7 竞品对标与差异化

| 对比维度 | 传统 ERP（如 SAP PP） | 通用 APS（如 Asprova） | 本产品 |
|:---|:---|:---|:---|
| **排程算法** | 无限产能 MRP | 有限产能 + 启发式 | MILP 精确优化 |
| **约束建模** | 固定逻辑 | 可配置 | 可配置 + 替代工艺/物料 |
| **目标优化** | 单一（按期交付） | 多目标启发式 | 多目标精确权衡 |
| **行业适配** | 通用 | 通用 | 离散制造深度适配 |
| **数据集成** | 自闭环 | 需二次开发 | 开箱即用 Excel + API |
| **价格** | 高 | 中高 | 中（差异化定价） |

## 二、核心应用场景

### 2.1 场景总览

| 场景 | 典型痛点 | 系统解决方案 |
|:---|:---|:---|
| **1. 接单排产** | 销售接单后无法快速判断能否按时交付 | 自动展开 BOM + 工艺路线 + 产能校核，秒级给出交期承诺（CTP） |
| **2. 多订单批量排产** | 数十/上百订单同时排产，人工排不过来 | 数学规划求解器一次性优化全部订单的工序排程 |
| **3. 插单/改单应对** | 紧急插单打乱原计划，人工重排耗时 | 增量排产，锁定已开工工序，仅重排未开工部分 |
| **4. 产能瓶颈识别** | 不清楚哪台设备/哪个时段是瓶颈 | 甘特图 + 资源负荷率热力图，直观定位瓶颈 |
| **5. 物料齐套分析** | 排了计划但物料不齐，无法执行 | BOM 展开后与库存/采购到货时间比对，提前预警缺料 |
| **6. 外协决策** | 自制产能不足时何时外协、外协给谁 | 对比自制成本 vs 外协价格，在产能约束下自动分配 |
| **7. 在制品管理** | 不清楚车间在制品状态和进度 | 录入完工进度，滚动排产时自动扣除已完成工序 |
| **8. 滚动排产** | 计划赶不上变化，需要周期性更新 | 按日/周滚动，冻结近期已下达计划，重排远期计划 |

### 2.2 典型业务模式

#### 按单生产（MTO）的订单排产

| 维度 | 说明 |
|:---|:---|
| **业务背景** | 客户下单后才开始排产，订单带有明确交期和延期罚金条款 |
| **核心痛点** | 产能不足时哪些订单优先交付、哪些延期损失最小难以人工判断 |
| **系统价值** | 以"销售收入 - 延期罚金"最大化为目标，自动给出订单优先级与交付方案 |
| **适用行业** | 机械装备、电子代工、模具制造、定制化零部件加工 |

#### 按库存生产（MTS）的产能均衡

| 维度 | 说明 |
|:---|:---|
| **业务背景** | 根据预测或安全库存组织生产，需在多产品间分配有限产能 |
| **核心痛点** | 旺季产能不足、淡季产能闲置，库存积压或缺货风险并存 |
| **系统价值** | 综合库存成本、产能利用率、缺货惩罚，给出各产品的均衡生产量 |
| **适用行业** | 日化、食品、建材、标准化零部件 |

#### 瓶颈产能下的加班/外协决策

| 维度 | 说明 |
|:---|:---|
| **业务背景** | 关键设备产能成为瓶颈，需决策是否加班、是否外协 |
| **核心痛点** | 加班成本 vs 延期罚金 vs 外协成本的三方权衡复杂 |
| **系统价值** | 模型内置加班、外协决策变量，自动给出成本最优的组合方案 |
| **适用行业** | 精密加工、半导体、印刷、注塑 |

#### 物料替代与采购联动

| 维度 | 说明 |
|:---|:---|
| **业务背景** | 原材料存在替代关系，采购到货时间影响生产排程 |
| **核心痛点** | 替代比例、采购提前期、库存水平多重耦合，人工难以统筹 |
| **系统价值** | 联动考虑替代比例约束、采购限制与库存平衡，输出采购与替代建议 |
| **适用行业** | 化工配方、食品原料、金属材料替代 |

### 3.2 流程步骤详解

| 步骤 | 操作内容 | 关键产出 | 参与角色 |
|:---|:---|:---|:---|
| **1. 订单录入** | 通过 API 从 ERP 拉取或手工录入客户订单（产品/数量/交期），设定优先级 | 订单池（含交期、数量、优先级） | 计划员 |
| **2. BOM 展开** | 根据产品代码递归展开 BOM 树，计算各层物料净需求 | 物料需求清单 | 系统（自动） |
| **3. 工艺匹配** | 匹配工艺路线，支持替代工艺选择 | 工序序列 + 设备/工装需求 | 系统（自动） |
| **4. 产能校核** | 统计各设备各时段负荷率，初步判断产能是否充足 | 产能负荷报告 | 系统（自动） |
| **5. 物料齐套** | 物料需求与库存/采购到货时间比对，标记缺料风险 | 齐套分析报告 | 计划员、采购员 |
| **6. 排产求解** | 运筹优化算法在多重约束下，生成工序级最优排程 | 最优排产方案（甘特图） | 系统（算法自动执行） |
| **7. 计划下达** | 确认后的计划下发至 MES / 车间电子看板 / 派工单 | 车间可执行工单 | 计划员、车间主任 |
| **8. 执行跟踪** | 车间完工反馈实时回传，比对"计划 vs 实绩" | 实时进度看板、偏差报告 | 计划员、车间主任 |
| **9. 滚动排产** | 发生异常或新订单时，冻结近期已下达计划，重排远期 | 更新后的可执行计划 | 计划员、系统（算法） |

> **闭环价值**：步骤 8 的实绩数据反馈直接修正步骤 6 的算法输入（如在制品状态、标准工时），形成"**排程 → 执行 → 反馈 → 优化排程**"的持续改进飞轮。

## 四、产品功能架构

系统采用五层分层架构，自下而上为**数据层 → 算法层 → 应用层 → 用户层**，并辅以**集成层**贯穿全局。

```
┌─────────────────────────────────────────────────────────────────────┐
│                          用户层                                      │
│   生产计划员  |  车间调度员  |  销售人员  |  管理层                   │
├─────────────────────────────────────────────────────────────────────┤
│                          应用层 (Web)                                │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│  │ 主数据    │ │ 排产控制  │ │ 结果展示  │ │ 分析看板  │ │ 系统管理  │ │
│  │ 管理      │ │ 中心      │ │ 甘特图    │ │ 负荷分析  │ │ 配置/权限 │ │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ │
├─────────────────────────────────────────────────────────────────────┤
│                          算法层                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ ┌─────────┐ │
│  │ 数据预处理    │  │ 模型构建      │  │ 求解引擎     │ │结果解析  │ │
│  │ (readCellDB/ │─▶│ (变量/约束/  │─▶│ (Gurobi      │─▶│(ProSta/ │ │
│  │  readTableDB)│  │  目标函数)    │  │  混合整数规划)│ │ ProEnd) │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ └─────────┘ │
├─────────────────────────────────────────────────────────────────────┤
│                          数据层                                      │
│  ┌──────────────────┐  ┌──────────────────┐  ┌────────────────┐   │
│  │ stg_ 原始数据层   │  │ core_ 核心数据层  │  │ alg_ 算法视图层 │   │
│  │ (Excel 导入落地)  │─▶│ (标准化主数据)    │─▶│ (排产输入视图)  │   │
│  └──────────────────┘  └──────────────────┘  └────────────────┘   │
├─────────────────────────────────────────────────────────────────────┤
│                          集成层                                      │
│   Excel 导入导出  |  REST API  |  ERP/MES 对接接口                  │
└─────────────────────────────────────────────────────────────────────┘
```

| 层级 | 职责 | 技术实现 |
|:---|:---|:---|
| **用户层** | 面向不同角色提供差异化界面 | 浏览器访问，基于角色权限控制 |
| **应用层** | 业务功能承载，连接用户与算法 | Flask Web 应用，Jinja2 模板 |
| **算法层** | 数据预处理 → 模型构建 → 求解 → 结果解析 | Python + Gurobi 混合整数规划 |
| **数据层** | 三层数据架构：原始 → 核心标准化 → 算法视图 | SQLite，stg_/core_/alg_ 视图 |
| **集成层** | 与外部系统数据交换 | Excel 导入导出 + REST API |

## 五、详细功能清单

> **标注说明**：✓ 已有基础（可直接复用） | ◐ 部分实现（需完善） | ✕ 待新建
> **优先级**：P0（MVP 必做） | P1（核心增强） | P2（高级功能） | P3（生态集成）

### 5.1 主数据管理

| 编号 | 功能 | 描述 | 现有基础 | 优先级 |
|:---|:---|:---|:---|:---|
| 1 | 物料主数据 | 产品/自制件/原材料三级分类管理，含库存上下限、持有成本 | ✓ `core_md_material` | P0 |
| 2 | BOM 管理 | 多层 BOM 维护，支持替代物料、虚拟件 | ✓ `core_biz_bom` | P0 |
| 3 | 工艺路线管理 | 多工序路线，支持替代工艺、工装绑定 | ✓ `core_biz_routing_*` | P0 |
| 4 | 设备资源管理 | 设备产能、可用时段管理 | ✓ `core_md_resource` | P0 |
| 5 | 工装管理 | 工装台账、工装数量约束 | ✓ 受 `nfixtable` 控制 | P0 |
| 6 | 原材料管理 | 原材料编码、采购提前期、库存 | ✓ `core_md_raw_ext` | P0 |

### 5.7 排产结果 KPI 指标体系

| KPI | 定义 | 计算方式 | 数据来源 | 优先级 |
|:---|:---|:---|:---|:---|
| **订单准交率** | 按时交付订单数 / 总订单数 | 计划完成时间 ≤ 客户交期 | 排产结果 | P0 |
| **设备综合利用率** | 设备总负荷 / 设备总可用产能 | 各工序加工时间 / 设备班次可用时间 | 排产结果 + 设备日历 | P0 |
| **设备 OEE** | 可用率 × 性能率 × 合格率 | 综合三率计算（需 MES 实绩） | 排产结果 + MES 实绩 | P1 |
| **平均延期天数** | 延期订单的延期天数均值 | Sum(计划完成 - 交期) / 延期订单数 | 排产结果 | P1 |
| **延期罚金总额** | 所有延期订单罚金合计 | Sum(延期天数 × 单位罚金) | 排产结果 | P1 |
| **总换型时间** | 所有设备换型时间合计 | Sum(各设备换型时间) | 排产结果 | P1 |
| **库存周转率** | 年销售成本 / 平均库存 | 排产结果 + 财务数据 | 排产结果 | P2 |
| **瓶颈设备负荷率** | 瓶颈设备负荷 / 可用产能 | 自动识别负荷率最高设备 | 排产结果 | P2 |
| **外协工时占比** | 外协加工工时 / 总加工工时 | 外协工序工时 / 全部工序工时 | 排产结果 | P2 |

### 7.2 与现有项目的关系

### 7.3 关键成功因素

| 因素 | 说明 |
|:---|:---|
| **算法是大脑，体验是手脚** | 优秀的算法是核心竞争力，但直观、流畅的交互界面同样关键 |
| **强调集成，而非替代** | APS 应定位为 ERP、MES 的增强型系统，通过标准接口协同 |
| **数据质量是生命线** | 算法再强，也依赖准确的设备参数、工时数据和BOM |
| **渐进式实施** | 先从一个车间、一条产线试点，验证效果后再推广 |

### 7.5 定价与商业模式

| 模式 | 说明 | 适用客户 |
|:---|:---|:---|
| **订阅制（SaaS）** | 按年订阅，按用户数 + 订单规模阶梯定价 | 中小企业，快速上线 |
| **买断制（On-Premise）** | 一次性授权 + 年服务费 | 大企业，数据安全要求高 |
| **混合模式** | 本地部署 + 年度运维服务 | 有 IT 能力的中大型企业 |

> 初期建议以 **订阅制 + 首年实施费** 为主，降低客户决策门槛。

## 十一、差距分析

从"现有能力"到"产品目标"的差距全景：

| 能力项 | 现有状态 | 目标状态（产品级） | 差距 | 改造工作量 | 优先级 |
|:---|:---|:---|:---|:---|:---|
| **数据输入** | Excel 手工导入 | Excel 导入 + ERP API 自动同步 | 需新增 API 集成 | 中 | P1 |
| **求解触发** | 命令行/IDE 运行脚本 | Web 界面一键触发 + 异步任务队列 | 需封装 API + Celery | 中 | P0 |
| **求解进度** | 控制台日志输出 | 前端实时进度展示 + WebSocket 推送 | 需新增进度回调机制 | 中 | P2 |
| **结果展示** | Excel 报表导出 | 甘特图 + 负荷图 + 多维度看板 | 需新建前端可视化模块 | 大 | P0 |
| **结果调整** | 修改 Excel 重新求解 | 甘特图拖拽调整 + 局部重排 | 需新增交互编辑能力 | 大 | P1 |
| **计划管理** | 无版本管理 | 版本存档 + 审批流程 + 冻结管理 | 需新建计划管理模块 | 中 | P1 |
| **约束配置** | 代码硬编码（nfixtable/nouttable） | 界面开关 + 参数在线调整 | 需抽象配置层 + 前端配置界面 | 中 | P1 |
| **目标配置** | 代码硬编码权重 | 界面权重配置 + 多目标可视化调整 | 需抽象目标配置层 | 中 | P1 |
| **用户权限** | 无 | 多角色 + 菜单级权限控制 | 需新增用户与权限模块 | 中 | P1 |
| **系统部署** | 本地 Python 环境 | Docker 标准化部署 | 需新增 Dockerfile + 编排 | 小 | P1 |

## 十二、附录A：现有算法能力总结

当前代码库的核心能力：

| 维度 | 现状 |
|:---|:---|
| **求解器** | Gurobi MILP（`MIPGap=0.0001`） |
| **决策变量** | 产品生产量、自制件生产量、库存、采购、设备负荷、加班、工装、订单销售/延期、外协、替代 |
| **目标函数** | 最大化利润 = 销售收入 - 延期罚金 - 原材料/外协/设备/工装/库存成本 - 产能不足惩罚 - 替代惩罚 |
| **约束体系** | 订单销售平衡、产品/自制件/原材料库存平衡、设备能力平衡、工装能力平衡、替代比例、批次、采购限制、期初/期末库存 |
| **数据输入** | BOM、工艺路线、设备、工装、订单、外协、原材料、在制品、替代关系、采购限制 |
| **数据载体** | Excel → DB（已有 Flask + 数据管理界面雏形） |
| **结果输出** | 订单销售、产品计划、自制件计划、采购计划、库存计划（Excel） |
