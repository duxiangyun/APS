## 一、设计概述

### 1.1 设计思路

```
求解结果（Gurobi .x / .Pi 属性）
    ↓ INSERT（长格式，3NF）
变量表（res_*）
    ↓ SQL PIVOT / JOIN 主数据
结果视图（res_view_*，宽格式，对应 Excel Sheet 的各子表）
    ↓ Web 展示 / Excel 导出
前端页面
```

### 1.2 长格式 vs 宽格式

| 格式 | 用途 | 示例 |
|---|---|---|
| **长格式**（变量表） | 存储求解结果 | `(run_id, material_code, route_id, period, quantity)` |
| **宽格式**（结果视图） | 对应 Excel Sheet 子表输出 | 行=产品，列=period_1~period_12 + 小计 |

长格式的优势：
- SQL 原生友好（`period` 是列值而非列名）
- `nperiod` 变化不影响表结构
- 视图层做 PIVOT 适配展示

> **PIVOT 列数约定**：当前 `PLAN_HORIZON = 12`，计划类视图 PIVOT 列为 `period_1 ~ period_12`；
> 库存类视图含 0 期初始库存（算法遍历 T0=0..nperiod），PIVOT 列为 `period_0 ~ period_12`（13 列）。
> 若计划期数调整，需同步修改视图 PIVOT 列数。

### 1.3 版本管理

每次求解生成一个 `run_id`，所有变量表通过外键关联。视图默认读取最新版本（`run_id = MAX(res_solve_run)`），支持历史版本对比。

### 1.4 表与视图的职责划分原则

| 层 | 存储内容 | 数据来源 | 示例 |
|---|---|---|---|
| **变量表（`res_*`）** | 变量的**原始求解值**（`.x` / `.Pi`）+ 定位下标（`run_id` + 维度键） | Gurobi 求解结果直接写入 | `quantity`、`load`、`dual_value` |
| **结果视图（`res_view_*`）** | **派生指标**：名称、单价、成本、收入、状态、比率等 | JOIN `core_*` 主数据后实时计算 | `revenue = quantity × price`、`delivery_status` |

**派生字段一律放视图，不存入表**，原因：

1. **消除冗余**：如 `revenue` 可由 `quantity × order.price` 算出，`shadow_price` 已在 `res_dual_prod` 中，重复存储会不一致
2. **单一数据源**：单价、费率、名称等以 `core_*` 主数据为准，主数据修正后视图自动反映
3. **表结构稳定**：表只随模型变量变化，展示口径调整只需改视图

各派生字段的计算依据（**口径与算法完全一致**，标注算法行号）：

| 派生字段 | 计算方式 | 依据 | 依赖的主数据表 |
|---|---|---|---|
| 销售收入 revenue | `交付量 × order.price` | L1264 | `core_biz_demand_order` |
| 延期罚金 delay_penalty | `交付量 × order.delay_penalty × (实际交期 − 交期)`，仅延期交付行 | L1265 | `core_biz_demand_order` + `res_order_sale` |
| 边际贡献 margin | `order.price − 影子价格` | L1269 | `core_biz_demand_order` + `res_dual_prod` |
| 交付状态 delivery_status | 5 态：按期交付 / 部分按期交付 / 部分按期 / 延期交付 / 未交付 | L1244-1262 | `core_biz_demand_order` + `res_order_sale` + `res_order_delay` |
| 采购成本 cost_total | `Σ期采购量 × purchase_cost` | L1462 | `core_md_raw_ext` |
| 外协成本 cost_total | `Σ期外协量 × outsource_price` | L1431 | `core_md_semi_ext` |
| 设备/工装正常成本 | `Σ负荷 × unit_cost` | L1594 / L1935 | `core_md_resource` |
| 设备/工装加班成本 | `Σ加班负荷 × unit_cost × overtime_cost_multiplier` | L1627 / L1942 | `core_md_resource` |
| **库存成本 inventory_cost** | **`Σ期库存量（含0期） × holding_cost_rate`** | L1487-1497 / L1512-1521 / L1537-1546 | `core_md_material` |
| 库存成本费率说明 | 算法直接使用输入的库存成本费率（`alg_named_*InvCost` = `holding_cost_rate`），**不做任何换算**（目标函数 L852-854 同口径） | L852-854 | — |
| 设备/工装能力 capacity | `每班时长 × 班次数 × 数量 × 利用率`（EquipCap/FixtCap，L702-711） | L702-711 | `core_md_resource` + `core_biz_global_params` |
| 最大/平均负荷率 | `MAX(负荷/能力)×100`、`Σ(负荷/能力)×100 ÷ 期数`（仅计负荷>eps 的期，除以总期数） | L1589-1593 | — |
| 不可行罚成本 | `松弛量 × 1e6`（算法罚系数 `penalty`，L713） | L713 | 常数 |
| 替代规则属性 | 规则类型/被替代料/替代料 | L1969-1971 | `core_md_alt_rule` |

## 三、表结构定义

### 3.1 通用字段约定

| 字段 | 类型 | 含义 |
|---|---|---|
| `run_id` | INTEGER | 求解批次号，外键关联 `res_solve_run`，复合主键首列 |
| `period` | INTEGER | 计划期序号；除库存三表外取值 1~nperiod，库存三表额外含 0（期初） |
| `quantity` | REAL | 变量原始求解值（Gurobi `.x`），仅写入 > eps（1e-4）的非零值 |
| `load` | REAL | 资源负荷工时（变量求解值） |
| `dual_value` | REAL | 约束对偶值（影子价格，Gurobi `.Pi`），仅 `intager=0` 时写入 |

未特别说明时，各变量表的**值字段均只存非零值**（阈值 eps=1e-4，与算法输出 Excel 的过滤口径一致）。

### 3.2 求解版本表 `res_solve_run`

每次求解插入一条，`run_id` 为自增主键，供所有结果表关联。

| 字段 | 类型 | 主键 | 含义 |
|---|---|:---:|---|
| `run_id` | INTEGER | ✓ | 求解批次号（AUTOINCREMENT） |
| `run_time` | TEXT | | 求解完成时刻（本地时间，程序写入时记录） |
| `objective` | REAL | | 目标函数值 = 总利润（Gurobi `ObjVal`） |
| `mip_gap` | REAL | | MIP 相对间隙（Gurobi `MIPGap`） |
| `solve_time_ms` | REAL | | 程序启动至求解完成的耗时（毫秒） |
| `status` | TEXT | | 求解状态：OPTIMAL / INFEASIBLE / TIME_LIMIT / SUBOPTIMAL 等（Gurobi Status 映射） |
| `nperiod` | INTEGER | | 计划期数（当前 12） |
| `intager` | INTEGER | | 1 = 整数规划；0 = 连续松弛（此时对偶解有意义） |
| `nfixtable` | INTEGER | | 工装表开关（1 = 输入存在），决定工装类变量是否写入 |
| `nouttable` | INTEGER | | 外协表开关（1 = 输入存在），决定外协变量是否写入 |
| `nrawlimtable` | INTEGER | | 关键原材料限制表开关 |
| `nsubtable` | INTEGER | | 替代关系表开关 |
| `nwiptable` | INTEGER | | 在制品表开关 |
| `created_at` | TEXT | | 记录创建时间（DDL 默认 `datetime('now','localtime')`） |

### 4.3 视图示例

**产品销售计划**（按产品聚合订单交付量，全部产品输出）：

```sql
CREATE VIEW res_view_prod_sale AS
WITH latest AS (SELECT MAX(run_id) AS rid FROM res_solve_run),
sale AS (
    SELECT o.product_code AS material_code, s.period, SUM(s.quantity) AS qty
    FROM res_order_sale s
    JOIN core_biz_demand_order o ON o.order_id = s.order_id
    WHERE s.run_id = (SELECT rid FROM latest)
    GROUP BY o.product_code, s.period
)
SELECT
    m.material_code,
    COALESCE(SUM(CASE WHEN sa.period = 1 THEN sa.qty END), 0) AS period_1,
    -- ... period_2 ~ period_12
    COALESCE(SUM(sa.qty), 0) AS quantity_total
FROM core_md_material m
LEFT JOIN sale sa ON sa.material_code = m.material_code
WHERE m.category = 'PRODUCT'
GROUP BY m.material_code
ORDER BY m.material_code;
```

**自制件计划**（wip 行由 `core_biz_wip × 默认工艺路线` 实时派生，变量表不存 wip）：

```sql
CREATE VIEW res_view_self_plan AS
WITH latest AS (SELECT MAX(run_id) AS rid FROM res_solve_run),
prod AS (
    SELECT sm.material_code, CAST(sm.route_id AS TEXT) AS route_id, sm.period, sm.quantity
    FROM res_self_made sm
    WHERE sm.run_id = (SELECT rid FROM latest)
),
wip AS (
    -- 完工周期 = 总制造期(WipMaxT) - 已完成阶段(WipStage)，数量 = 在制数量
    SELECT w.material_code, 'wip' AS route_id,
           h.total_lead_time - w.completed_stages AS period, w.quantity
    FROM core_biz_wip w
    JOIN core_biz_routing_header h
      ON h.material_code = w.material_code AND h.is_default = 1
    WHERE w.quantity > 0
),
allrows AS (SELECT * FROM prod UNION ALL SELECT * FROM wip)
SELECT
    ROW_NUMBER() OVER (ORDER BY r.material_code, r.route_id) AS seq,
    r.material_code, r.route_id,
    -- ... period_1 ~ period_12 (SUM CASE PIVOT)
    SUM(r.quantity) AS quantity_total
FROM allrows r
GROUP BY r.material_code, r.route_id
HAVING SUM(r.quantity) > 0.0001
ORDER BY r.material_code, r.route_id;
```

**设备正常负荷**（能力与负荷率口径对齐算法 EquipCap，L702-705 / L1589-1594）：

```sql
CREATE VIEW res_view_equip_load AS
WITH latest AS (SELECT MAX(run_id) AS rid FROM res_solve_run),
gp AS (
    SELECT CAST(MAX(CASE WHEN param_key='SHIFTS_PER_PERIOD'      THEN param_value END) AS REAL) AS shifts,
           CAST(MAX(CASE WHEN param_key='SHIFT_DURATION_MINUTES' THEN param_value END) AS REAL) AS minutes,
           CAST(MAX(CASE WHEN param_key='PLAN_HORIZON'           THEN param_value END) AS REAL) AS nperiod
    FROM core_biz_global_params
),
agg AS (
    SELECT resource_code,
           -- ... period_1 ~ period_12 (SUM CASE PIVOT)
           SUM(load) AS load_total,
           MAX(CASE WHEN load > 0.0001 THEN load END) AS max_load,
           SUM(CASE WHEN load > 0.0001 THEN load ELSE 0 END) AS active_load
    FROM res_workload
    WHERE run_id = (SELECT rid FROM latest)
    GROUP BY resource_code
    HAVING SUM(load) > 0.0001
)
SELECT
    a.resource_code,
    r.quantity * r.utilization_rate * gp.minutes * gp.shifts AS capacity,
    -- ... period_1 ~ period_12
    a.max_load    * 100.0 / NULLIF(r.quantity * r.utilization_rate * gp.minutes * gp.shifts, 0)
        AS max_load_rate_pct,
    a.active_load * 100.0 / NULLIF(r.quantity * r.utilization_rate * gp.minutes * gp.shifts, 0) / gp.nperiod
        AS avg_load_rate_pct,
    a.load_total * r.unit_cost AS normal_cost_total
FROM agg a
JOIN core_md_resource r ON r.resource_code = a.resource_code
CROSS JOIN gp
ORDER BY a.resource_code;
```

**产品库存**（成本口径 = Σ期库存量 × holding_cost_rate，对齐算法 L1487-1497，无任何换算）：

```sql
CREATE VIEW res_view_prod_inv AS
SELECT
    pi.material_code,
    SUM(CASE WHEN pi.period = 0 THEN pi.quantity ELSE 0 END) AS period_0,
    -- ... period_1 ~ period_12
    SUM(pi.quantity) AS quantity_total,
    SUM(pi.quantity) * m.holding_cost_rate AS inventory_cost
FROM res_prod_inv pi
JOIN core_md_material m ON m.material_code = pi.material_code
WHERE pi.run_id = (SELECT MAX(run_id) FROM res_solve_run)
GROUP BY pi.material_code, m.holding_cost_rate
HAVING SUM(pi.quantity) > 0.0001
ORDER BY pi.material_code;
```

## 六、约束条件说明

约束条件本身**不写入数据库**。原因如下：

| 内容 | 本质 | 是否存 DB | 原因 |
|---|---|---|---|
| 约束定义（`ProdBal`、`CapBal` 等） | 模型逻辑 | 否 | 写在代码中，结构固定，不随求解变化 |
| 约束系数（BOM 系数、工艺工时等） | 输入数据 | 已存 | `core_biz_bom`、`core_biz_routing_step` 等表 |
| 约束的解（对偶值/影子价格） | 输出结果 | 存 | `res_dual_*` 系列表 |
| 约束的松弛量（不可行量） | 输出结果 | 存 | `res_infeasible` 表 |

> 约束是"代码"，不是"数据"。数据库存数据和结果，不存代码逻辑。
